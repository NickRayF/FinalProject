# «Итоги года» — frontend

Личный репозиторий с frontend-частью командного проекта «Итоги года». **GoOffer — название команды, а не продукта.** История изменений выделена из общего репозитория через `git subtree`, поэтому здесь сохранены коммиты, относящиеся к папке `frontend`.

Исходный командный проект: [GoOffer_HackathonAvito](https://github.com/NikName2021/GoOffer_HackathonAvito).

Онлайн-демо: [statistics-helper.ru](https://statistics-helper.ru/).

## О проекте

«Итоги года» превращают демонстрационную активность пользователя на площадке объявлений в персональную интерактивную историю. Пользователь выбирает профиль, открывает статичную имитацию главной страницы сервиса и запускает recap со слайдами, графиками, достижениями, сравнением с прошлым годом, прогнозом и миссиями на следующий год.

Все профили, объявления, просмотры и переходы на целевые страницы используются только для демонстрации кейса. Интеграции с реальными пользовательскими данными и торговыми операциями нет.

## Мой вклад

Frontend проекта реализован мною. Основные части работы:

- архитектура React-приложения, маршрутизация, адаптивный интерфейс и переиспользуемые компоненты;
- авторизация через backend-сессию и хранение клиентского состояния аккаунта в Redux Toolkit;
- создание, просмотр, редактирование и удаление тестовых профилей;
- ручной ввод и массовый импорт объявлений и просмотров из JSON с клиентской валидацией;
- статичная адаптивная имитация главной страницы площадки и шаблонные страницы действий;
- интерактивный recap: открытие подарка, слайды, свайпы, CTA, диаграммы и анимации;
- отображение рассчитанных backend показателей, сравнений годов и ориентировочного прогноза без повторного расчёта на frontend;
- выбор до трёх миссий на следующий год и отображение их прогресса в итогах и профиле;
- экспорт выбранных итогов в PNG и создание временных публичных ссылок только для разрешённых карточек;
- административный интерфейс: CRUD дополнительных recap-карточек и редактирование встроенных ачивок, включая выбор и загрузку иконки;
- отправка продуктовых событий, обработка состояний загрузки и ошибок API;
- unit- и E2E-тесты, ESLint, Prettier и production-сборка.

Авторство отдельных изменений можно проверить по истории коммитов и через `git blame`.

## Ключевая логика

- Backend формирует готовый recap и рассчитывает бизнес-показатели. Frontend отвечает за визуализацию и пользовательский сценарий.
- Поля `comparison` и `forecast` используются как готовые данные: показатели и оценки не пересчитываются в браузере.
- Миссии выбираются набором до трёх элементов; их прогресс и статус приходят с backend.
- Публичная страница получает только безопасный снимок выбранных карточек по временному токену и не запрашивает профиль или полный recap.
- Встроенные ачивки можно редактировать, но нельзя создавать и удалять. Дополнительные recap-карточки поддерживают полный CRUD.
- Продуктовые события отправляются независимо от основного UI: ошибка аналитики не прерывает просмотр итогов.

## Запуск

Полный проект с backend, PostgreSQL, Redis и frontend запускается через Docker Compose из корня [общего репозитория](https://github.com/NikName2021/GoOffer_HackathonAvito#readme):

```bash
docker compose up -d --build
```

В этом личном репозитории находится только frontend, поэтому для его отдельного запуска нужны Node.js 22+ и доступный backend API.

Windows PowerShell:

```powershell
npm ci
Copy-Item .env.example .env.local
npm run dev
```

Linux/macOS:

```bash
npm ci
cp .env.example .env.local
npm run dev
```

После запуска откройте <http://localhost:5173>. Адрес API задаётся в `.env.local`:

```dotenv
VITE_BASE_API_URL=http://localhost:8000/api
```

## Основные интеграции API

| Возможность | Назначение |
| --- | --- |
| Auth | регистрация, вход, выход и восстановление сессии |
| Profiles | CRUD профилей, объявления, просмотры и миссии профиля |
| Recap | генерация персональных итогов, сравнение и прогноз |
| Missions | множественный выбор миссий и получение прогресса |
| Shares | создание безопасной ссылки и публичная загрузка по токену |
| Events | отправка событий просмотра recap и CTA |
| Card definitions | CRUD дополнительных карточек для администратора |
| Achievement definitions | редактирование встроенных ачивок для администратора |

## Пользовательский путь

1. Пользователь входит в аккаунт и выбирает или создаёт тестовый профиль.
2. Открывает статичную страницу площадки и запускает «Итоги года».
3. Открывает подарок и листает персональные слайды.
4. Изучает показатели, сравнение, прогноз, достижения и рекомендации.
5. Выбирает миссии, скачивает изображение или создаёт временную публичную ссылку.

## Ограничения демонстрации

- проект не подключён к реальным серверам и данным площадки;
- целевые страницы CTA являются шаблонными;
- публичные ссылки временные и содержат только выбранные разрешённые карточки;
- внешние изображения имеют локальные fallback, чтобы интерфейс оставался понятным при сетевых ошибках.

## Использование AI-инструментов

AI-инструменты применялись для обсуждения вариантов интерфейса, поиска причин ошибок, подготовки черновых решений и документации. Архитектура, типизация, интеграции, пользовательские сценарии и итоговый код проверялись и дорабатывались вручную.

## Лицензия и материалы

Проект создан в учебно-демонстрационных целях. Страница площадки является статичной имитацией без реального торгового взаимодействия.
